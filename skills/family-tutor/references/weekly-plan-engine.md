# 周计划引擎（2026-09-12 起执行）

## 0. 核心设计原则

**用户原话**：「学习进度由学生的作业进行判断，这样就无需跟进学校进度。当学生的作业开始变为单元复习或期末，其中复习的时候，ai需要立刻察觉到并将本周末的学习计划由查漏补缺＋预习调整为查漏补缺＋单元/全方面复习。」

**关键判定**：学生学到了哪、复习到哪 = 看作业里出现什么，不看日历。系统不主动推学校进度，而是**被动跟随 + 智能响应**。

---

## 1. 三种周模式

| 模式 | 触发条件 | 周计划内容 | 试卷 |
|---|---|---|---|
| **预习周**（默认） | 学生作业都是新课内容（单课练习、课后题） | 查漏补缺 + 预习下一课 | 周末小测（课后习题级） |
| **单元复习周** | 学生作业出现「单元复习 / 综合练习 / 单元小结」 | 查漏补缺 + 单元复习 | 单元复习卷（单科 15–25 道） |
| **期中/期末周** | 学生作业出现「期中复习 / 期末复习 / 期中测试 / 期末测试」 | 查漏补缺 + 全范围复习 | 混搭卷（单科 30–40 道） |

**默认进入「预习周」，识别到复习信号才切换。**

---

## 2. 复习信号识别（SOP）

### 2.1 信号源

**主信号**：学生上传的作业（图片 / 文字 / 文档）
**辅助信号**：
- 学生口述（"今天做单元复习了"）
- 学生上传的试卷标题
- 错题集里的内容（如果单元卷错题涌入也说明在复习）

### 2.2 关键词词典

**单元复习信号**（任一命中即触发）：
- `单元复习` / `单元小结` / `单元综合` / `单元检测` / `单元测试`
- `Unit Review` / `Unit Test` / `综合练习` / `回顾与整理`
- KP 归属密度突增：一次作业里 ≥ 5 个 KP 全属同一单元（说明是单元复习作业）

**期中/期末复习信号**（任一命中即触发）：
- `期中复习` / `期中测试` / `期中模拟` / `期中考试`
- `期末复习` / `期末测试` / `期末模拟` / `期末考试`
- `月考` / `阶段测试` / `综合检测`
- KP 归属密度：一次作业里 KP 覆盖 ≥ 4 个不同单元（混搭特征）

### 2.3 判定流程（脚本侧）

```
学生提交作业（图片/文字）
       ↓
[Step 1] vision / 文本提取 → 列出题目列表
       ↓
[2] 对每道题执行 KP 归属（参考 classify-homework.py）
       ↓
[3] 信号聚合：
       - 作业标题含关键词？→ 命中
       - KP 覆盖：单元数？同单元 KP 数？
       ↓
[4] 决策：
       - 命中期中/期末信号 → 模式 = "期中/期末周"
       - 命中单元复习信号 → 模式 = "单元复习周"
       - 否则 → 模式 = "预习周"
       ↓
[5] 写入 学习状态.json.current_mode
       ↓
[6] 触发周计划生成（重算本周末计划）
```

### 2.4 模式切换的延迟要求

**用户原话**：「AI 需要立刻察觉到」。要求：
- 学生提交作业后 ≤ 5 分钟内识别并更新模式
- 周计划当晚（如有作业）就反映新模式
- 学习规划.md 顶部显示当前模式横幅

### 3.1 周计划输出位置

```

```

每次模式切换后**增量更新**：在最新一周追加或修订。

### 3.2 周计划模板（预习周）

```markdown
## Week 12（2026-09-14 ~ 2026-09-20）
**当前模式**：预习周（数学 u3、英语 u1、语文 u1）
**学生最近 7 天表现**：数学 u1.k2 错了 3 次 → 标薄弱

### 每日安排

**周一（数学）**
- 课后练习：分数除法 u1.k2（同 KP 错 3 次，追加 2 道同类题）
- 错题回灌：u1.k2 原题重做 1 遍

**周二（语文）**
- 预习：《草原》u1.k2 重点字词
- 课后：从题库抽 u1.k2 拼音 + 字义各 1 道

**周三（英语）**
- 新课：Unit 1 Growing up u1.k2 (talk about our future)
- 课后：单词默写 10 词

**周四（数学 + 语文）**
- 数学：u1.k3 分数除法应用题
- 语文：u1.k2 句子理解

**周五（英语 + 错题复盘）**
- 英语：u1.k2 句型转换（be able to / can）
- 全科错题复盘：本周错题各做 1 道

**周末**
- 周测：单元小测卷（自动生成）
- 预习：下周一新课

### 错题回灌清单
- 数学 u1.k2（同 KP 错 3 次）→ 已包含 2 道同类题
- 语文 u2.k5 近义辨析错 2 次 → 包含 1 道

### 薄弱 KP（master < 60%）
- 数学 u1.k2 分数除以整数（master=40%）
- 语文 u2.k5 近义词辨析（master=50%）
```

```markdown

### 每日安排

- 数学 u1 单元复习（6 个 KP 全部过一遍）
- 语文 u1 单元复习（6 个 KP，含生字 + 古诗 + 阅读）
- 英语 u1 单元复习（6 个 KP，含单词 + 句型 + 情景）

**周四–周五（错题集中攻克）**
- 三科错题集里本周新增的错题 → 重做 + 同类题回灌

**周末**
- 单元复习卷（数学 + 语文 + 英语，各 1 套）
- 听写包：英语 u1 单词 + 语文 u1 生字
- 背诵检查表：语文 u1 必背课文

### 错题回灌清单
- 数学 u1.k2（错 3 次）→ 3 道同类题
- 语文 u1.k5（错 2 次）→ 2 道同类题
- 英语 u1.k3（错 1 次）→ 1 道同类题
```

```markdown

### 每日安排

**周末**

[自动列出范围 + 掌握度 + 建议复习时长]
```

## 4. 错题回灌规则（每周末自动追加）

### 4.1 规则

**用户原话**：「每周的试卷一定要抽一两个错题放进模拟试卷。」

具体：
- 每周模拟卷（无论哪种模式）必须包含 ≥ 1 道错题回灌题
- 期中/期末模拟卷必须包含 ≥ 2 道
- 错题回灌题从错题集匹配同 KP 同类型的题（详见 exam-formats.md §3.2）

### 4.2 同类题匹配优先级

1. 题库里同 KP 不同 qid 的题（首选）
2. 题库没有 → LLM 改写原错题（数字/情境替换）
3. LLM 也没有合适的 → 原错题重做（标"复习原题"）

### 4.3 错题回灌的执行位置

- 单元复习卷末尾
- 期中/期末卷第二部分"应用题"
- 默写卷挖空区
- 听写包必含词

## 5. 周计划与 KP 掌握度联动

### 5.1 KP 掌握度计算

每个 KP 维护 `master` 值（0–100），更新逻辑：

```
master_new = master_old × 0.6 + (本次得分/100) × 40 + 修正值
- 答对：得分 = 100，master += 10
- 答错：得分 = 0，master -= 5
- 连续 3 次答对：额外 +15
- 连续 3 次答错：额外 -10
```

### 5.2 薄弱 KP 的判定

`master < 60%` → 标薄弱 → 周计划自动加入专项练习

### 5.3 周计划排序原则

- **预习内容**：按 KP 顺序（不跳过）
- **薄弱 KP**：插入到当周任意一天（强制覆盖）
- **错题回灌**：紧跟薄弱 KP 之后
- **新预习**：薄弱 KP 处理完后再排

## 7. 模式稳定期（防抖动）

**问题**：学生可能偶尔上传一份零散的旧作业，导致误识别为复习信号。

**解决**：
- 信号必须有 ≥ 2 次独立确认（如 2 次作业都命中关键词）才切模式
- 例外：明确关键词（"期中模拟卷"、"期末复习"）命中即切
- 模式切换有冷却期：7 天内不可从"复习周"切回"预习周"（除非学生显式说"回到新课"）

## 8. 周计划自动化

### 8.1 触发
- 每周一首次交互（或跨周后的首次交互）→ 生成/更新当周计划（**不用 cron**，见 §8 触发实现）
- 模式切换时 → 立即跑
- 学生新作业批改完成时 → 检查是否需要重排

### 8.2 触发方式（用户明确：不用 cron，电脑不常开）

```python
cronjob_manage(action="create", schedule="0 22 * * 0",
    name="weekly-plan-generator",
    prompt="运行 generate-weekly-plan.py，根据当前模式和学习状态.json 生成下周计划")
```

## 10. 边界情况

| 情况 | 处理 |
|---|---|
| 学生同时报三科作业 | 三科独立判断模式，互不影响 |
| 学生口述"我们开始复习了" | 直接信，更新模式 |
| 学校发了复习提纲但学生还没做 | 信号=0，不切模式（等真作业） |
| 考前 2 周 vs 考前 1 周 | 优先看作业信号，考前 1 周作业必然是复习 |
| 学生周六才上传作业（周末中途进入） | `day-schedule.py`：周末拆 3 步（周测卷→错题本复盘→预习下周新课）；周六=卷+复盘、周日=预习；交付附「明天再来」 |
| 长假第 3 天才提交作业 | `day-schedule.py`：把 2 周期+预习按剩余天数摊派（不足自动合并）；交付附「明天再来」 |
| 假期/周末最后一天才来 | 全部步骤压缩到当天；提示「明天起按周计划」 |
| 寒暑假 | 模式 = "自主预习"（不计学校进度） |
| 学生跨年级（转学） | 重新初始化 KP 索引 + 学习状态.json |

## 11. KPI（确保规则有效）

每月自检：
- 模式切换准确率 ≥ 90%（人工抽查 10 个切换点）
- 周计划覆盖率 = 100%（每周都有计划）
- 错题回灌命中率 ≥ 80%（抽 5 个错题，检查下次是否再错）
- 学生/家长对周计划的接受度（口述反馈）

## 12. 中途进入的剩余安排（2026-10-10 用户要求）

**背景（用户原话）**：「遇到了周末，学生周六才上传作业——ai 应该安排周日的学习计划告知学生，让学生明天再来找 ai 完成明天的学习任务，而不是周日空着。长假也是——五一/十一第三天才提交作业，应该安排后几天的学习安排。」

**工具**：`scripts/day-schedule.py`（`--date` / `--json`；`FAMTUTOR_TODAY` 可覆盖“今天”，测试/补排用）

- 判定今天所处学习块：周末（剔除调休上班的周六日）/ ≥3 天假期（第 N 天、还剩几天）；工作日、调休上班日 → 无剩余安排。
- 拆步（沿用周期规则）：
  - 周末（1 周期）：周测卷 → 错题本复盘 → 预习下周新课
  - 3 天小长假（1 周期）：复习 → 错题卷 → 查漏补缺+错题本
  - 5/7/9 天（2 周期+预习）：周期1（复习→卷→补漏）→ 周期2（同）→ 预习课
- 摊派：步骤按剩余天数从左到右均衡铺开（每天 ceil(剩余步骤/剩余天数)）。
  - 剩余 < 总天数（进入晚）→ 合并执行 +「注：进入较晚…顺延」；剩余 > 步骤 → 富余日标「机动」。
  - 最后一天进入（周日/假期末日）→ 全部压缩到当天，提示「明天起按周计划」。
  - 输出含固定提示：「→ 明天（MM-DD 周X）记得再来找 AI，完成当天的学习任务。」

**落点三处（缺一不可）**：
1. `学习规划.md`：`generate-weekly-plan.py` 刷新时自动写「📍 剩余安排」段（`<!-- REMAINING:BEGIN/END -->` 包裹）。
2. `错题清单`（day1-pipeline ⑤）：清单末尾自动附「📅 剩余安排（周末/长假中途）」段。
3. 交付消息：Hermes 必须把该段 +「明天再来」提示放进消息（与 §0.5 三条提醒并列）。

**实测示例**（国庆第 3 天提交，剩 5 天；`day-schedule.py --date 2026-10-03` 真实输出）：

```
📅 剩余安排（国庆节·假期第3天/共7天，还剩 5 天）
- 今天（10-03 周六）：周期1 复习（薄弱 KP 优先）；周期1 错题卷（回灌★必做）+ 订正
- 明天（10-04 周日）：周期1 查漏补缺 + 错题本；周期2 复习（薄弱 KP 优先）
- 10-05（周一）：周期2 错题卷（回灌★必做）+ 订正
- 10-06（周二）：周期2 查漏补缺 + 错题本
- 10-07（周三）：预习课（1 课时）+ 预习小试卷
- 注：进入较晚——完整计划已按剩余天数合并执行；做不完的优先完成「订正/错题本」，其余往后顺延

→ 明天（10-04 周日）记得再来找 AI，完成当天的学习任务。
```
